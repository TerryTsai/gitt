gitt reads ordinary bare repositories and working checkouts in one directory. It creates empty repositories. Git transport and all other changes belong to your existing Git and SSH tools.

Browsing

Files shows disk contents for a checkout, or the default branch for a bare repository. Refs opens committed snapshots. Changes separates staged, unstaged, and nonignored untracked files. Comparison shows the difference between two endpoint snapshots.

Boundaries

Source previews and each diff side are limited to 1 MiB and 20,000 lines. Highlighting is limited to 256 KiB, with plain text fallback. Committed raw downloads are limited to 8 MiB. Pages are limited to 2 MiB of HTML. Markdown is limited to 40,000 parse events and 128 levels of nesting. Larger content remains accessible with local Git or SSH.

Discovery stops at repository boundaries, skips symlink directories, and scans at most 10,000 directories and 1,000 repositories. History pages contain 50 commits; listings contain 200 entries per page. Repositories are read as they exist now; working files may change while you browse.

Supported storage

Self-contained SHA-1 repositories with loose or packed objects and refs. Linked worktrees, separate Git directories, external object stores, SHA-256, reftable, and sparse or split indexes are unsupported. Submodule entries and LFS pointer files can be inspected; their contents are not fetched.

Access

There are no application accounts. Anyone who can reach this server can read and create repositories. Expose it only to your intended users. Ignored files are excluded, but tracked files and their history remain visible.
