# Implementation decisions

The user approved the requirements and technical direction, then authorized implementation and remaining routine decisions on 2026-11-13. This record distinguishes product requirements from implementation choices.

| Choice | Reason and consequence |
| --- | --- |
| git2 0.21 / bundled libgit2 1.9.7, network features disabled | Cohesive local Git APIs and a standalone executable. Installed Git is used only to generate and verify development fixtures and by separately configured SSH transport. |
| Evaluate gitoxide, retain git2 for v0.1 | Current gitoxide can handle staged status; it was not rejected for lacking that feature. A second backend would add unproven maintenance cost. |
| Axum / Hyper / one-thread Tokio runtime | Explicit connection and blocking-work limits. Two active Git/render operations, four waiting operations, 16 connections. Raw downloads read committed blobs through the same bounded Git jobs. No separate worker service. |
| Askama + embedded CSS/templates | Autoescaped outer document, audited escaped fragments, zero browser JavaScript. |
| Compact phone layout | The approved mockup uses a small breadcrumb header with middle ellipsis, visible Files/History/Branches/Tags navigation, and the selected branch, tag, or commit as plain text at the right of the tab bar. File actions sit alongside the breadcrumb; no separate information bar separates tabs from content. Creation is on home. Compare and commit detail views and routes are removed. Remove Menu, Refresh, duplicate headings, page introductions, and routine file-status labels. Semantic elements remain the styling hooks; only syntax spans have classes and line anchors have IDs. |
| Per-path Git metadata | Show size, Git mode, last-change commit message, author, and commit age. All list rows use distinct columns on one line at every viewport width, with keyboard-focusable horizontal scroll regions. Columns remain visible without wrapping or clipping. All list views use shared styles: 7 px vertical cell padding, 12 px column gaps, 20 px line height, left-aligned columns, a flexible first column, and the same primary/metadata link treatment. Row separators use a subtle half-CSS-pixel rule; row text shares the same family and size except for commit hashes. No per-view or phone-only row-spacing overrides. File modes display owner/group/other permissions as `rw- r-- r--` or `rwx r-x r-x`; directory modes display `-`; symlink and submodule entries name their kind because their Git modes do not encode regular-file permissions. Repository rows show the selected revision (HEAD by default), latest commit, author, and commit age; only the visible repositories are opened and only their selected commit is read, capped at 1 MiB. Empty repositories retain their branch, while unavailable metadata leaves dashes without failing discovery. Bound history lookup to the visible 200 entries and share request-local object reads. Directory identity includes all descendants; merge history follows the first parent with matching path state. Renames are additions at their new path. Missing/shallow history or lookup limits leave metadata unavailable with an explicit notice. No database or background indexing. |
| pulldown-cmark + Ammonia | Restricted Markdown; repository HTML is displayed as text. Images become alt text. Relative links stay within the selected repository snapshot. |
| syntect, per-language compiled packs with Oniguruma | The preferred pure-Rust fancy-regex backend retained 23–28 MiB with concurrent source requests, exceeding the unchanged 16 MiB idle target. Curated packs alone did not fix it. Bundled Oniguruma brought the measured source-only retained RSS below 8 MiB, with complete highlighting of the 64 KiB fixture. YAML grammar compilation runs at build time; each request loads only its language and dependencies. Plain text remains available. |
| Linux Landlock ABI ≥3 and openat2 required | Kernel confinement applies to library reads too. Startup fails if enforcement is unavailable. The development host has ABI 2, so runtime acceptance testing occurs on the target host. |
| Disable libgit2 owner validation in this process only | The explicitly configured root is the shared-group boundary. Kernel confinement is installed before worker threads. No existing safe.directory or repository config is changed. |
| Exclude system/global Git configuration and clear GIT_* environment | Avoid implicit redirects, helpers, and machine-specific behavior. No shell or executable repository hooks/filters are called. |
| Single exact browser origin, explicit on wildcard bind | Host validation and same-origin creation prevent DNS rebinding and cross-origin writes. Forwarded headers are not trusted. |
| Signed expiring form token and SameSite=Strict cookie | Creation is an explicit protected POST; no state-changing GET. Origin and token checks do not authenticate users. |
| Descriptor-relative private staging + rename without replacement | A service-owned 0700 reserved directory protects stage names from other group members. A temporary initialization thread adds a pinned write-only Landlock policy and blocks path-based chmod/chown probes; libgit2 uses umask mode. Only newly staged content receives shared modes before atomic no-replace publication. Existing repositories are not chmodded. |
| SHA-1 / ordinary refs / self-contained storage | SHA-256, reftable, redirected Git directories, alternates, and linked worktrees are explicitly unsupported. No automatic conversion. |
| Committed content only | Files defaults to HEAD in both repository layouts. Preview, raw, Markdown links, and search use committed objects and retain the selected reference or commit ID. Do not read the working tree or index; remove Changes and its route. Empty repositories expose no working files. Never run clean/smudge/textconv helpers. The creation form uses a checked Bare toggle; lists omit repository kind. |
| MIT project license, Cargo.lock committed | Small reusable utility with reproducible dependency selection. Third-party licenses accompany release artifacts. |
| No implicit service installation or exposure of existing personal repositories | Validate using isolated synthetic fixtures; ship OpenRC and systemd examples. Default listener remains localhost. |

Limits are observable product behavior, not claims of hard per-request preemption. A response timeout cannot interrupt a running C function; permits remain held until it exits. A named selection resolves when loading each page but stays named in links and the toolbar; an explicitly selected commit remains fixed even when HEAD moves. Branch and tag links use qualified references so equal branch/tag names remain distinct. Revision links change only rev and keep the current route and all other parameters. Repository-list selections additionally identify the relevant repository and update its row. The toolbar value is plain text. Search form submissions redirect to canonical query URLs, removing temporary scope fields before revision links are rendered. An administrator or machine user who can place data inside the watched root controls what is visible there.

The README and performance report record measured outcomes, including any target that was not met. The target numbers are not silently raised.

Creation retains one reserved `.gitt-create-private-UID` directory with a marker. It reuses that private directory and never sweeps interrupted stages. Grouping directories created for failed operations may remain empty. Each active creation can use one short-lived 256 KiB-stack initialization thread while its normal work permit remains held. This is needed because Landlock restrictions cannot be removed from a reusable worker.

A 24 MiB shared native allocation budget additionally bounds libgit2 malloc/realloc, including packed delta bases. This is not a whole-process RSS guarantee. A verified fixture producing five bytes from a 64 MiB delta base returns 422 and the server remains available. Each HTTP connection has a 120-second lifetime, so stalled downloads cannot hold all 16 slots indefinitely. A timed-out creation explicitly warns that its operation may still finish.

All browser form contexts preserve non-UTF-8 filename bytes using internal hexadecimal hidden fields; navigation URLs use percent-encoded original bytes. Markdown is limited to 40,000 events and 128 nested elements.

Oniguruma is initialized before threads with 16,384 match-stack entries and one million match/search retries, in addition to the per-file size, line-length, and cooperative time limits. The C regex backend is an explicit measured tradeoff against the initial pure-Rust preference; it adds no runtime library dependency. Full release workload measurements are recorded separately in performance.md.

The compact layout uses 11 px source text with 16 px line spacing, following the user's request to go smaller than the 12 px mockup. Line numbers use 9 px text with an intrinsic gutter and 5 px separation. Ordinary source begins within 130 CSS pixels of the document top. Breadcrumbs keep the current location visible; a native **…** disclosure opens all parent folders, retaining byte-preserving snapshot links. Tab names are not repeated in the breadcrumb. Exceptional names truncate without expanding the page, with the full location in the title. A Search link styled as a button stays fixed at the top right on every page. It opens /search, with repository-name search or file-path search within a selected repository. Opening it from a repository preserves the selected branch, tag, or commit; changing repository in the form resets to that repository’s HEAD. Scope options preserve repository bytes with hexadecimal values, including a repository at the watched root. Search pagination retains the scope and revision selection. Inputs share the 13 px list font. The home Create button sits beside Search and shares its fixed placement, font, padding, and border. Raw-file links are omitted from file views and preview errors; binary/oversized-file messages point to local Git. Browser checks cover 320 and 390 px phones and desktop, light/dark, with JavaScript disabled. Operational limit notices remain visible.

File-list metadata has a 75 ms cooperative time budget, 512 distinct commits, 4096 object reads, 32,768 traversal steps, 1 MiB per metadata object, and 32 MiB cumulative object bytes. A request-local tree cache holds at most 64 trees or 2 MiB of raw tree data. These limits bound additional history work without claiming native calls can be preempted. Source bytes and displayed size come from the selected commit; last-commit fields describe its history.

The stylesheet URL includes a hash of its embedded contents so an updated executable does not reuse a previous build's hour-long CSS cache.

The earlier compact UI deployment used one blocking worker to reduce retained memory. It serialized every Git/render operation and shared that worker with Tokio raw-file reads. The current deployment allows two Git/render jobs, so one slow native call does not block unrelated navigation. Queue waits are capped at two seconds and browsing responses at ten seconds (creation retains thirty seconds). Timed-out jobs are aborted if not yet running; running native calls retain their permits until completion. Operations taking at least 500 ms, queue exhaustion, and timeouts log a request number, route, and timing without query parameters. A focused regression verifies navigation during a stalled Git job. The user-reported intermittent hang was not reproduced during the direct-origin checks; the confirmed worker bottleneck is fixed, with logging to diagnose further incidents. Earlier preliminary three-reader trials retained 13,520–17,740 KiB, so the 16 MiB idle target is not consistently met. Further resource testing was stopped at the user’s explicit request to deploy. The published v0.1.0 performance figures describe the older release, not this build.
